# 第二时代特色兵换代

本地实现：七条换代线，新增五种单位，沿用江防精练寨兵与关镇长值兵。全部500人，不新增科技节点，不改变版本号；尚未安装或发布。科技卡片的国家筛选与画面表现须另作实机确认。

| 地区 | 原单位 | 第二时代单位 | 原版科技ID |
|---|---|---|---|

原版科技的研究费用、前置、普通单位和建筑解锁保持不变。数据构建阶段从本机原版读取两份科技文件，只追加七条单位解锁。回归检查逐节点移除追加字段后，比较全部原版token；原版文件更新后必须重新构建并复核。

第二时代精锐只对原属圈国家开放；客籍议约仍保留基础兵种资格。招募还必须掌握本圈第一时代军制、保持HBE成员身份，并满足原单位的当地建筑、实际就业、运转机构、役负、义气或驻防议约条件。没有年份和最终地区任务门槛。

原版科技已研究但本圈基础军制未研究时，二代兵仍不可招募。原版科技不增加HBE整体研究门槛。江防、关镇的后期政制科技仅移除单位解锁，保留其原有国家收益和晚期资格。

## 最终基础属性

下表已计入时代与单位类别继承，未计国家、经验、将领或其他科技加成。负的承伤表示减伤。

茶路选骑保留轻骑兵的地形与损耗代价：山地战斗−5%，丛林与湿地−10%，损耗+20%。没有追加移速减益。两种现有重步兵的基础战斗属性不变。

`copy_from`的数字按增量填写。二代步兵模板1000人，填`max_strength = -0.5`；二代骑兵模板400人，填`max_strength = 0.1`。完整目标与增量由`data/age2_military.json`统一定义，验证器重新递归计算原版类别和时代模板。

## 费用与共同额度

维护继续使用物资和市场价格。普通二代步兵、重步兵、义仓兵、骑兵分别额外消耗0.01、0.02、0.005、0.01工具维护系数，其他基础物资沿用现有九折配方。劲弩制作增加木材与少量工具；两种重步兵改用原版早期重步兵装备配方。

十四种单位共用原有`hbe_civic_special_family`额度；役负计数覆盖全部十四种，每种计一次。旧队升级仍用原版`upgrades_to`和付费换装操作，不删除重建部队。队数没有净增长就不新增役负，净增一队仍增加2点役负。已有旧版重步兵保持存在，新招募按新的科技与本圈资格检查；不自动补发其他科技。

五种新增单位复用前身连续插画及原版裁切方式，不另建重复DDS，不覆盖科技或兵种GUI。

## 开发入口

- 配置：`data/age2_military.json`
- 构建阶段：`tools/build_age2_military.py`，接在完整构建的发布元数据阶段之后。
- 验证：`tools/validate_age2_military.py`，已接入`tools/validate_mod.py`。
- 单独应用阶段：`python -B tools/build_age2_military.py --root C:/github/holy-bashu-empire --game "D:/SteamLibrary/steamapps/common/Europa Universalis V/game"`

阶段可重复执行，不应改变已经生成的文件。静态检查、隔离引擎检查和真实画面验证分开报告；未验证的界面行为不记作通过。
